Which packages work

Every night a job takes the latest release, installs common packages with apt on an Android emulator, one at a time, and runs a short test of what each one is for: a Python script, a compile, a server answering a request. These are the latest results, failures included. The page changes when a result does.

    How to read this

    The emulator is an x86_64 machine running the arm64 APK through Android's translator, because GitHub has no ARM machines with an emulator. Some failures look like they come from that translator and not from Cortex, they're marked, and stay listed as failures until a phone shows otherwise. Each package is installed on a clean system with --no-install-recommends and tested within 5 minutes.

    Something you use isn't here?

    The list lives in tests/e2e/compat.sh, one line per package. Open an issue or a pull request and it gets tested every night from then on. The logs of every run are in the workflow runs.
